# KubeDeck: план серии обучающих видео

Статус: план зафиксирован 2026-10-15, производство отложено. Версия продукта на момент плана: 2.30.1.

## Решения

- **Аудитория:** публичная серия (YouTube), для админов и DevOps, которые впервые открывают KubeDeck.
- **Язык:** только русский. Голос + субтитры (русские). Английской версии не будет.
- **Формат:** запись экрана с голосом; один ролик - одна задача зрителя, 3-7 минут.

## Принципы

- **Сквозная история.** Все ролики снимаются на одном демо-кластере с одними и теми же «поломками», поэтому каждый начинается с одинакового состояния.
- **Задача, а не кнопки.** Не «вот вкладка YAML», а «поправим лимит и проверим dry-run».
- **Шаблон ролика:** 10 секунд «что научимся делать» → действие → 15 секунд «итог и где ещё пригодится».
- **Версия в кадре.** В начале каждого ролика указана версия (2.30.x); при каждом минорном релизе сверять с release notes, какие ролики перезаписать.

## Демо-стенд

Тот же, на котором сняты скриншоты презентации 2.30 (`docs/kubedeck-2.30-presentation.html`):

- k3s v1.37 в WSL Ubuntu как временный systemd-юнит; `docker.io` через зеркало `mirror.gcr.io` в `/etc/rancher/k3s/registries.yaml` (Docker Hub из WSL не отдаёт слои).
- `kubedeck-demo`: storefront-api (3 реплики, ConfigMap + Secret, HPA, PDB, Ingress), checkout-worker с цветными логами, payment-gateway в CrashLoopBackOff, legacy-billing в Pending (request 64 CPU), inventory-sync с несуществующим образом, redis-cache (StatefulSet), log-shipper (DaemonSet), nightly-report (CronJob), storefront-loadtest для истории потребления.
- `kubedeck-staging`: storefront-api с другим образом и лимитами - для сравнения манифестов.
- Аккаунт `oncall-viewer` с правом только читать поды в `kubedeck-demo` - для ролика про права.

Сырые файлы стенда лежат в [`scripts/demo-cluster/`](../scripts/demo-cluster/): `k3s-get.sh` (скачать k3s со сверкой sha256), `k3s-mirror.sh` (зеркало и запуск), `demo.yaml`, `loadgen.yaml`, `viewer.sh` (аккаунт oncall-viewer и его kubeconfig), `fake-node.sh` (эмулированная нода под давлением, только для кадра). Пути в скриптах временные. **Перед записью** превратить их в один скрипт подъёма с README, чтобы стенд поднимался одной командой.

## Требования публичной серии

- В кадре только демо-данные: никаких реальных кластеров, хостов, путей пользователя, токенов. Демо-секреты явно помечены как ненастоящие.
- Единый кадр: 1920×1080, тема «Стальной графит», русский интерфейс, увеличенный шрифт терминала; мелкие места приближать на монтаже.
- Субтитры из текста озвучки (сценарий пишется заранее и становится `.srt`).
- Описание: главы с таймкодами, ссылка на релиз и на соседние ролики; обложки в одном стиле.
- Трейлер (0) делается последним, из готового материала.

## Починить до записи

То, что иначе попадёт в кадр и устареет после патча:

- «Подогнать столбцы по содержимому» обрезает статус из нескольких слов («MemoryPressu», «Available Prog»).
- Панель SSH на ноду не переведена на русский.
- Аккаунт без права list namespaces на уровне кластера помечает кластер как «Кластер недоступен» (расходится с обещанием 2.24.2).

## Следующие шаги

1. Починить пункты выше.
2. Довести `scripts/demo-cluster/` до подъёма одной командой.
3. Написать сценарии с текстом озвучки, начиная с роликов 1-3.
4. Пилот: записать ролик 3, проверить звук, кадр, субтитры, затем остальные.
