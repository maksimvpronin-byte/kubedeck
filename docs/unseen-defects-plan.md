# KubeDeck — долг, который тесты не видят

Статус: план составлен 2026-08-29, ни одна секция не начата. Порядок — по
убыванию отдачи. Секция A закрывает причину, B и C — два известных её следствия,
D — гигиена, из-за которой открытые пункты не находятся глазами.

## Контекст

За один день 2026-08-29 в выпущенном коде нашлись три дефекта, каждый из которых
видел любой пользователь и не видел ни один тест:

| дефект | сколько прожил | чем был пойман |
|---|---|---|
| `Р’В·` вместо `·` в командной палитре | 2.20 → 2.23.2, три релиза | глазами |
| выделение в редакторе съедало текст (2.0–2.4:1) | 2.15 → 2.23.3, восемь релизов | скриншотом от владельца |
| hover карточки Related прятал подпись (1.7:1) | не датирован | арифметикой по всем темам |

Общая причина одна. Набор тестов держит контракты, но часть из них читает
исходник как текст: они помечены в коде как `grep contract` и в собственном
комментарии описаны честно — «ломается на переименовании, пропускает настоящую
регрессию». Регулярное выражение над `.tsx` не может увидеть ни цвет, ни то, что
происходит по клику.

Считать их надо по самой пометке, а не по любому упоминанию: в шапке каждого
тестового файла есть строка, объясняющая, что такое `grep contract`, и грубый
`grep -c "grep contract"` принимает её за заглушку. Первая редакция этого плана
на этом и ошиблась — «70» было 55 заглушек плюс 15 таких пояснений. Правильная
команда:

```bash
grep -rc "^\s*// grep contract:" apps/desktop/tests/*.cjs | grep -v ':0$'
```

Распределение на момент составления плана — **55 заглушек**:

```
10  renderer-controllers    4  resource-usage        2  bulk-actions
 9  resource-table          3  yaml-editor           2  boot-screen
 6  workspace-tabs          3  watch-and-loading     1  resource-detail
 6  release-surface         2  namespace-selection   1  problems-panel
 4  theme                   2  drawer-lifecycle
```

**Инструмент для их замены уже есть и уже применялся.** 2.22.8 принёс jsdom и
`tests/helpers/dom.cjs` с `loadComponent`/`mount`, а шапка
`resource-table-dom.contract.test.cjs` говорит прямо: «These replace grep
contracts: what a row does when it is clicked… Every one of them used to be a
regular expression over `ResourceTable.tsx`, or nothing at all». Тринадцать
тестов в двух файлах доказывают, что подход работает. Программа продолжает
начатое, а не заводит новое.

Для цвета инструмент появился 2026-08-29: `tests/helpers/contrast.cjs` считает
WCAG-контраст по всем семи темам и держит правило «краска сохраняет минимум 45 %
своего контраста и не падает ниже 2.3:1». Им уже закрыты редактор и Related.

## Правила программы

- Секции независимы, порядок — по убыванию отдачи. **Секция A даёт основную
  часть пользы**, C — самая рискованная и идёт последней осознанно.
- Каждая секция — **отдельный релиз** (patch-bump, CHANGELOG, release notes,
  regression checklist — см. `docs/release-checklist.md` и
  `release-contract.json`). Не смешивать секции в один коммит.
- Ни одна секция не меняет пользовательское поведение. Если по ходу выясняется,
  что меняет — это отдельная запись в CHANGELOG и явный пункт в regression
  checklist.
- **Каждый новый тест проверяется на способность падать.** Тест, который не
  показали падающим на том дефекте, ради которого он написан, не считается
  написанным. Это правило появилось из трёх находок выше и не обсуждается.
- Заглушка не удаляется, пока её не заменил тест, проверяющий то же самое по
  существу. Уменьшение числа — не цель; цель — чтобы за каждым контрактом стояло
  поведение.
- После каждой секции — полный gate.

поведение. Часть из них честно неконвертируема (см. критерий), и это нормально.

Порядок по файлам — по населённости и по близости к тому, что ломалось:

- [ ] `renderer-controllers.contract.test.cjs` — 10 заглушек, самый населённый.
  **Начато:** три вокруг `LlmTab` переведены в `llm-tab-dom.contract.test.cjs`
  (шесть поведенческих тестов), осталось 7.
- [ ] `resource-table.contract.test.cjs` — 9; частично уже начато в
  `resource-table-dom.contract.test.cjs`, продолжить там же.
- [ ] `workspace-tabs.contract.test.cjs` — 6.
- [ ] `theme.contract.test.cjs` — 4; здесь же проверить, не дублирует ли часть
  из них правило из `helpers/contrast.cjs`.
- [ ] `resource-usage.contract.test.cjs` — 4.
- [ ] Остальные файлы (по 1–4 штуки) — по мере надобности, не самоцель.
- [ ] `release-surface.contract.test.cjs` — 6 — рассмотреть **отдельно**: это
  контракты о структуре релиза, а не о поведении UI, и для них grep может быть

Для каждой конвертируемой заглушки:

Критерий секции: число `grep contract` в наборе уменьшилось, и **для каждой
оставшейся заглушки в её комментарии сказано, почему она остаётся** — например,
контракт о структуре файла или о конфигурации сборки, где поведения нет. Полный

## Общий критерий

Дефект, который видит пользователь, должен быть виден и тесту — либо в плане
записано, почему для этого места это невозможно. Программа не закрыта, пока
секции A, B и D не пройдены; C может остаться открытой осознанно, как она уже
однажды осталась, но тогда это записывается здесь явно и с датой.
