# KubeDeck 2.9.2 — план исправления визуальных багов

Статус: сбор дефектов и реализация подтверждённых исправлений.

## Цель

Собрать и исправить небольшие визуальные дефекты интерфейса после 2.9.1 без
редизайна, новых dependencies и изменений backend-контрактов.

## Реестр дефектов

| ID | Поверхность | Симптом | Ожидаемое поведение | Статус |
|---|---|---|---|---|
| V-001 | Terminal Workspace | Проверить на свежей сборке, что Pod xterm и Node SSH действительно занимают всю высоту после resize | Контент активного терминала следует за верхней границей панели без пустой области | Нужна проверка на свежем build |
| V-002 | Overview / Capacity | `Group by` сжат в узкую вертикальную кнопку; подписи и значения CPU/RAM/Storage перекрываются и обрезаются | Полноразмерный тематический selector и читаемые метрики во всех карточках | Реализовано, ожидает ручной screenshot-check |

## V-002 — selector и метрики Capacity

### Сценарий воспроизведения

1. Открыть Overview кластера, в котором доступно несколько вариантов
   группировки Capacity.
2. Выбрать группировку по label, например `env`.
3. Открыть экран в тёмной теме и разместить три или больше групп в строке.
4. Проверить `Group by` и правую колонку метрик каждой карточки.

Приложенный скриншот подтверждает дефект на широком окне. Точную платформу,
масштаб интерфейса и размеры окна нужно записать при ручной перепроверке.

### Подтверждённые причины

- `OverviewPanel` уже использует общий `ThemedSelect`, но полное оформление его
  trigger и options сейчас привязано к terminal toolbar. На Overview остаётся
  узкий control без нормальной компоновки текста и chevron.
- Для label-группировки `label` и `description` могут одновременно содержать
  одно значение (`env`), поэтому selector показывает его дважды.
- Capacity card разрешено сжиматься до `260px`, хотя внутри находятся кольца
  фиксированной ширины `180px`, gap `18px` и legend. Для подписей и числовых
  значений не остаётся гарантированной ширины.
- Responsive `@container` для Capacity объявлен, но у Capacity-родителя нет
  собственного `container-type`; правило не переключает узкую карточку в
  вертикальный layout.

### Минимальное исправление

- Сохранить существующий `ThemedSelect` и его keyboard/listbox поведение; новые
  компоненты и UI-зависимости не добавлять.
- Добавить для Overview полноценные themed styles trigger/menu/options:
  стабильную минимальную ширину, горизонтальную компоновку, фиксированный
  chevron, видимые focus/hover/selected states и меню не уже trigger.
- Не выводить `description`, когда она совпадает с видимым `label`.
- Задать сетке Capacity минимальную ширину карточки от фактического содержимого:
  кольца плюс читаемая legend. На меньшей ширине переходить с трёх колонок на
  две и одну, а не сжимать текст.
- Сделать `.overview-capacity-group` query container и до пересечения подписей
  перестраивать rings и legend в один столбец.
- Гарантировать legend место для `AVAILABLE`/`ALLOCATABLE` и tabular numeric
  values; ellipsis оставить только как защиту на экстремальной ширине.

### Проверка

- [x] Selector одинаково читаем в закрытом и открытом состоянии; `env` не
  дублируется.
- [x] Существующее keyboard/listbox поведение и глобальный focus ring сохранены.

  Storage без перекрытия.
- [x] Layout поддерживает 1, 2 и 3 карточки в строке и перестраивает узкую

- [ ] Проверены Light и минимум одна тёмная тема.

## V-003 — renderer показывает JS-чанк

### Подтверждённая причина

В packaged-режиме navigation guard разрешал главному окну переход на любой
`file://` URL. Поэтому переход на lazy chunk мог заменить весь интерфейс
исходным minified JavaScript.

### Исправление и проверка

- file-навигация разрешена только на `dist/renderer/index.html`;
- переходы главного окна на файлы из `dist/renderer/assets` блокируются;
- contract фиксирует allowlist для renderer entrypoint;
- runtime-check в собранном Electron принудительно назначил окну URL
  `yamlFolding-*.js`: окно осталось на `index.html`, React root сохранился.

Для уже сломанного окна требуется перезапуск приложения. Проверку финального
packaged artifact выполнить после сборки общего релиз-кандидата 2.9.2.

## Правила патча

- исправлять первичный CSS/layout owner, а не добавлять компенсации в каждый
  компонент;
- переиспользовать существующие tokens и responsive patterns;
- сохранять Light и все тёмные темы;
- не менять поведение ресурсов, WebSocket, PTY, SSH и Gateway;
- не добавлять новые UI-библиотеки или state manager;
- один дефект — минимальный diff и один сфокусированный renderer contract;
- ручные пункты не отмечать выполненными без фактической проверки UI.
